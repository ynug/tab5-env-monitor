# Tab5 環境モニター 仕様書 v1.1

最終更新: 2026-10-17（v1.1: 軽量化のため WiFi・NTP・おやすみモード・グラフの期間切り替えを廃止し、手動の時刻設定と SD カードへの CSV 書き出しを追加）

M5Stack Tab5 に自作センサー基板（SCD41 / SHT35 / BMP581）を接続し、CO2・温度・湿度・気圧をリアルタイム表示・24時間記録・音声アラームする据え置き型モニター。

---

## 1. ハードウェア

### 1.1 本体: M5Stack Tab5

| 項目 | 内容 |
|---|---|
| SoC | ESP32-P4（RISC-V デュアルコア）, PSRAM 32MB, Flash 16MB |
| 画面 | 5インチ 1280×720 **横向き**で使用（パネル素の向きは縦 720×1280 → PPA で回転） |
| 液晶/タッチ | **ST7123 または ST7121**（ILI9881C+GT911 初期型は対象外）。起動時に内部I2C 0x55 の FW バージョンで自動判別（3=ST7123, 1=ST7121）。手元の 1 台目は **ST7123**（2026-10-17 確認）。ESP32-P4 チップ rev v1.3 → CPU 360MHz |
| WiFi | 内蔵 ESP32-C6。**使わない**（v1.1 で廃止） |
| microSD | SDMMC 4bit（G39〜G44）。CSV の書き出しに使う（§6.2.1） |
| 音声 | ES8388 コーデック + 内蔵スピーカー |
| RTC | RX8130（バッテリー非搭載のため電源断で時刻が失われる可能性あり → §6.4） |
| 電源 | USB-C 常時給電（バッテリーなし） |

### 1.2 センサー基板（自作）

| IC | I2C | 測定 | 設定 |
|---|---|---|---|
| SCD41 | 0x62 | CO2・温度・湿度 | VDD/VDDH=3V3 |
| SHT35 | 0x44 | 温度・湿度（高精度） | ADDR=GND, ALERT/nRESET 未接続 |
| BMP581 | 0x47 | 気圧・温度 | SDO=3V3, CSB=3V3（I2Cモード）, INT 未接続 |

- 電源: **3.3V 専用**（LDO なし）
- プルアップ: SDA/SCL とも 4.7kΩ → 3V3_SENSOR
- コネクタ: **Qwiic**（JST SH 1.0mm）1:GND 2:3V3 3:SDA 4:SCL
- 製造データ: `hardware/EnvMonitor_SCD41-SHT35-BMP581_I2C/`（[hardware/README.md](../hardware/README.md)）

### 1.3 接続（実測済み 2026-10-17）

Tab5 **PORT.A**（HY2.0-4P）: `GND / Ext5V / G53(SDA) / G54(SCL)`

| 測定 | 値 | 判定 |
|---|---|---|
| Ext5V–GND | 4.5〜4.7V | LDO 入力として十分 |
| G53–GND / G54–GND | 0.05V | Tab5 側プルアップなし → 5V 印加の危険なし。プルアップはセンサー基板の 4.7kΩ のみ |

※ 側面の ExtPort2（6ピン）は使用しない。

**変換アダプタ**: PORT.A の 5V を 3.3V レギュレーターで降圧し、SDA / SCL はそのまま Qwiic でセンサー基板へつなぐ。

- ⚠️ Grove 5V を Qwiic 赤線に直結しない（BMP581 の絶対最大定格超過）
- センサー基板を接続する前に、Qwiic 3.3V–GND が約 3.3V であることを確認する
- 基板版（`hardware/grove2qwiic-3v3/`）: レギュレーターは ME6211C33（1µF + 10µF のセラミックで安定）。手配線版は BA33DD0T + 22µF 電解

### 1.4 I2C バス設定

- ポート: G53(SDA) / G54(SCL)、内部 I2C（G31/G32）とは別バス
- クロック: **100kHz**（Grove 20cm + Qwiic 200mm で約 40cm, 4.7kΩ で立ち上がり約 0.4µs の見積もり。400kHz は規格 300ns を超えるうえ、バス使用率 1% 未満で利点がないため不採用）。設定で変更可能にしておく
- 設置: センサー基板は Tab5 の**横か下**に置く（真上・背面・同じケース内は不可）。画面最大輝度と消灯で 30 分ずつ比べ、温度差 0.2℃ 以内を目安に確認する
- ESP32-P4 の内部プルアップは無効（外付け 4.7kΩ を使う）
- 起動時に PORT.A の 5V 出力（EXT5V_EN, IO エキスパンダ経由）を ON にする

## 2. ソフトウェア構成

### 2.1 開発環境

- **ESP-IDF v5.5 系**（ネイティブ。Arduino は使わない）
- LVGL v9 + esp_lvgl_port
- Tab5 BSP（ST7123/ST7121 両対応の版を使う。足りなければ自前で補う）
- WiFi は使わない（v1.1 で廃止。内蔵の ESP32-C6 は起動しない）

### 2.1.1 表示パイプライン（手順1で実装）

- LVGL は PARTIAL モードで、内部 SRAM の帯バッファ（1280×32 ライン × 2、計 164KB）に描画。PSRAM に置くと約 3 割遅い（手順5では WiFi に内部 RAM を譲るため PSRAM に置いていた）。起動後の内部 RAM の空き 約 64〜73KB
- 描き終わった帯を PPA で 90°回転して、表示していない側の DPI フレームバッファへ非同期に書き込み、その間に CPU は次の帯を描く。フレームの最後に次のフレーム開始で切り替え
- DPI フレームバッファは 3 枚を順に使う。各バッファが見逃したフレームの変更範囲は、描画開始時（`LV_EVENT_REFR_START`）に LVGL の無効化範囲へ加えて描き直す。全画面の PSRAM→PSRAM コピー（45ms）より描き直し（約 30ms）の方が速いため。それ以降に無効化された範囲だけ、表側から PPA でコピーする
- フレームバッファは画面から外れて VSYNC 2 回経過するまで書き込まない → 書きかけが表示されない
- 実測（手順3）: スワイプ中の全面再描画 130ms → 42ms（約 24fps）。律速は PSRAM 帯域（液晶への送り出しが常時 約 107MB/s）。PPA の回転と無回転コピーは同じ速さ（全画面 45ms）で、CPU 回転は 756ms と遅い
- LVGL の描画ユニットはソフトウェア 1 つだけ。2 つ（2 コア）や LVGL の PPA 描画（塗りつぶし）は、実測でかえって遅かったため使わない（下表）。帯は PPA に渡すので `CONFIG_LV_DRAW_BUF_ALIGN=128`（L2 キャッシュライン）は残す
- **PPA の制約（実測）**: 90°回転で転送が完了しないことがある。幅の狭い領域（608×66）と、全幅でも帯の高さ（＝回転後の幅）24 / 66 で発生し、10 / 16 / 20 / 32 / 42 / 64 / 74 では発生しなかった。無効化領域を常に全幅・上下 8 ライン単位に丸め、帯の高さも 8 の倍数（32）にしている。PPA の完了待ちは 200ms で打ち切り、画面が固まらないようにしている
- **XIP from PSRAM**: プログラムと読み出し専用データ（フォント）を起動時に PSRAM へ写して実行。フラッシュは DIO 80MHz と遅く、描画が大きく改善（スワイプ中 60〜90ms → 47〜60ms、小さな更新 26〜63ms → 14〜26ms）
- センサー画面のミニグラフは、更新時（10 秒ごと）だけ小さなキャンバスに描く。折れ線オブジェクトのままだと帯ごとに 240 本の線を描き直し、全面再描画が最大 500ms になっていた
- 実測（v1.1 の軽量化、センサー⇄設定のスワイプ 6 回、全面再描画の平均）:

| 構成 | 平均 | 最大 |
|---|---|---|
| 手順5（PSRAM の帯 64 ライン、描画ユニット 2 + PPA 描画） | 60.6ms | 64ms |
| 帯を内部 SRAM（32 ライン）に | 42ms | 81ms |
| ＋描画ユニット 1 | 33ms | 42ms |
| ＋PPA 描画なし | 29ms | 37ms（ほかに、スワイプ後の最初の小さな更新で追いつきコピー 45〜60ms） |
| ＋見逃した範囲を描き直す（追いつきコピーなし） | 28〜31ms | 37ms |

  スワイプ中は約 32〜35fps。律速は CPU での描画（PPA の回転待ちは 1ms 未満）
- 指を離してからページが切り替わるまでのアニメーションは LVGL の既定 200〜400ms（ページ切り替えは常に 400ms）を半分の 100〜200ms にした（トップの CMakeLists.txt で `SCROLL_ANIM_TIME_MIN/MAX` を定義。設定画面などのスクロールアニメにも効く）
- 起動時に内部 I2C（G31/G32）のバス復旧（SCL 9 クロック + STOP）を行う。転送途中のリセットで IO エキスパンダの初期化が失敗し abort した事象への対策
- 上下反転（設定）は回転角 90°/270° の切り替えとタッチ座標の変換で対応
- esp_lvgl_port は表示に使わない（BSP の依存として 2.8 系に固定。2.9 は IDF 5.5.2 非対応）

### 2.1.2 開発用シリアルコンソール（`CONFIG_UI_DEBUG_CONSOLE`）

- USB-C（USB Serial/JTAG）経由で `shot`（画面を RLE+base64 で送信）、`tap X Y`、`drag X1 Y1 X2 Y2 MS`、`press X Y` / `release`、`ping`、`sound N`（アナウンス再生）、`sim co2|temp|hum|pres 値|off`（模擬センサーの値を固定）、`clock UNIX秒`（時刻を設定、設定画面と同じ処理）、`sd export`（SD への書き出し）

- 製品版では無効化する

## 3. センサー処理

### 3.1 取得

| センサー | 方式 | 周期 | 10秒値の作り方 |
|---|---|---|---|
| SHT35 | シングルショット, High repeatability, クロックストレッチなし | 1s | 10サンプルを外れ値除去して平均 |
| BMP581 | Normal mode, OSR 圧力×16 / 温度×2 程度, IIR 弱め | 1s | 10サンプルを外れ値除去して平均 |
| SCD41 | 周期測定（5s）、data ready をポーリング | 5s | 2サンプルの平均 |

SCD41 の初期化手順: stop_periodic_measurement（500ms 待つ）→ シリアル番号と ASC の状態を読む → ASC が設定と違えば set → start_periodic_measurement。ASC は persist_settings しない（センサーの EEPROM を消耗させないため、起動のたびに設定から入れ直す）。設定で ASC を切り替えたときは、センサーのタスクが次の 1 秒で止めて入れ直して再開する。
起動直後の最初の数回は捨てる（ウォームアップ。SHT35 2 回・BMP581 3 回・SCD41 2 回。再初期化・手動校正のあとも同じ）。

**実装（手順7、`components/sensors/backend_real.c`）**
- PORT.A に I2C バス（ポートは自動選択、100kHz、内部プルアップなし）を作る前に、SCL 9 クロック + STOP でバスを解放する（内部 I2C と同じ処理、`board_i2c_recover`）
- 起動時に 0x44 / 0x47 / 0x62 を確認してログに出す。1 つも応答しなければ模擬センサーで動く（記録は `REC_FLAG_SIM`）。設定画面の診断「センサー（PORT.A）」に各センサーの応答の有無を出す
- BMP581: ソフトリセット → チップ ID 0x50 と NVM の状態を確認 → スタンバイで IIR（気圧 係数 1、温度なし）・OSR（気圧 ×16、温度 ×2）を設定 → Normal 5Hz。データは 0x1D から 6 バイトを 1 秒ごとに読む
- SHT35: ソフトリセットとステータス読み出しで確認。1 秒ごとにシングルショット（0x2400）→ 16ms 待って 6 バイト
- SCD41: 1 秒ごとに data ready を見て、あれば read_measurement。CO2 が 0 の値は捨てる
- バスのアクセスはすべて排他（手動校正は UI のタスクから呼ばれ、SCD41 を止めて約 1 秒かかる。その間はセンサーの読み出しが待つ）
- CRC 計算と値の変換は `components/core/sensor_codec.c`（ホスト単体テストでデータシートの例と照合）

### 3.2 補正

| 対象 | 内容 |
|---|---|
| CO2 気圧補正 | BMP581 の 1分平均気圧を **1分ごとに SCD41 へ送る**（set_ambient_pressure） |
| SCD41 温度 | 自己発熱で高めに出るため、SHT35 との差を長期移動平均で学習してソフトウェアでオフセット補正（SCD41 内部メモリには書かない） |
| SCD41 湿度 | SCD41 自身の温度基準の相対湿度を、飽和水蒸気圧（Magnus 式）で SHT35 温度基準に換算 |
| 気圧 | 現地気圧のまま（海面気圧換算はしない） |

### 3.3 信頼性

1. CRC-8（Sensirion, 多項式 0x31）検証、タイムアウト、3回リトライ
2. バスが固まったら復旧（SCL を 9 クロック → STOP）→ センサーを再初期化。実装: 5 回続けて読めなかったセンサーは外したことにし、30 秒ごとにバスを作り直して（解放してから）探し直す。起動時に無かったセンサーも 30 秒ごとに探す
3. 物理範囲チェック: CO2 400〜40000ppm / 温度 −10〜60℃ / 湿度 0〜100% / 気圧 300〜1250hPa
4. Hampel フィルタ（窓 5, 中央値 ± 3·MAD を外れたら除外）
5. 1分値: 10秒値 6個の平均 + 最小・最大。**有効数 3 未満は欠測**（グラフ上は線を途切れさせる）
6. 代わりのセンサーへの切り替え: SHT35 が不調のときは温度を BMP581 → SCD41補正値の順、湿度を SCD41補正値で代用し、画面に「代替」表示
7. 整合性チェック: SHT35 と BMP581 の温度差が 2℃ を超えた状態が 10 分続いたら「要確認」表示

### 3.4 表示用の平滑化（記録とは別系統）

- 記録値（10秒/1分）は平滑化しない
- 表示値は適応型 EMA（1€ フィルタ方式）: ノイズは抑え、本当の変化には素早く追従
- （300ms の数値アニメーションは不採用: 表示分解能 0.1 の変化では中間値が出ず効果がないため。滑らかさは One Euro フィルタで確保）
- 最下位桁にヒステリシス（表示中の値から 0.75 桁以上離れるまで表示を変えない）
- 傾向矢印: 直近 10 分の傾き（↗ → ↘）

### 3.5 記録する系列（1分値）

| # | 系列 | 単位 | 画面での採用 |
|---|---|---|---|
| 1 | CO2（SCD41, 気圧補正済み） | ppm | ◎ CO2 |
| 2 | 温度 SHT35 | ℃ | ◎ 温度 |
| 3 | 温度 SCD41 生値 | ℃ | |
| 4 | 温度 SCD41 補正値 | ℃ | |
| 5 | 温度 BMP581 | ℃ | |
| 6 | 湿度 SHT35 | %RH | ◎ 湿度 |
| 7 | 湿度 SCD41 生値 | %RH | |
| 8 | 湿度 SCD41 補正値 | %RH | |
| 9 | 気圧 BMP581（現地） | hPa | ◎ 気圧 |

各系列について 平均・最小・最大・有効数 を持つ。

## 4. 派生指標（採用中の温度・湿度から計算。追加の保存は不要）

| 指標 | 式 |
|---|---|
| 露点 | Magnus 式（a=17.62, b=243.12℃） |
| 不快指数 | DI = 0.81T + 0.01H(0.99T − 14.3) + 46.3 |
| 暑さ指数 WBGT（室内推定） | WBGT ≈ 0.725T + 0.0368H + 0.00364·T·H − 3.246 |

- 画面に出すのは暑さ指数だけ（温度カードの右上、色の丸 + 「暑さ指数 20 ほぼ安全」。値は切り捨ての整数で、段階と一致させる）。段階（日常生活に関する指針）: 〜21 ほぼ安全 / 〜25 注意 / 〜28 警戒 / 〜31 厳重警戒 / 31〜 危険。丸の色: ほぼ安全=緑、注意・警戒=黄、厳重警戒・危険=赤。熱中症アラーム（§8）もこの値で判定
- 露点と不快指数は画面・グラフに出さない（v1.1。露点は結露の目安だが常時は不要、不快指数は暑さ指数と役割が重なる）。SD カードの CSV には 3 つとも書き出す

## 5. 画面

### 5.1 全体

- 横向き 1280×720、ダークテーマ（常時表示向け）
- トップ: `lv_tileview` で 3 ページ、左右スワイプで切り替え、ページインジケータ付き

```
[センサー（ホーム・起動時）] ⇄ [設定] ⇄ [デモ]
```

- 表示分解能: CO2 1ppm / 温度 0.1℃ / 湿度 0.1% / 気圧 0.1hPa
- CO2 カードの状態表示: 色の丸 + 文字（〜1000 良好 / 〜1500 注意 / 1500〜 警告）。色だけで区別しない
- 湿度カードの状態表示: 色の丸 + 文字（〜35 乾燥 / 〜70 良好 / 70〜 多湿）。丸の色: 乾燥=黄、良好=緑、多湿=青
- 値の数字の色: 通常は文字色、アラームの閾値（§8.1）に達したら色を変える。5 分待たずに表示中の値ですぐ判定し、単位・見出しの色は変えない
  - CO2: 1000〜 黄 / 1500〜 赤
  - 温度: 16℃ 以下 青 / 暑さ指数 25〜（警戒）黄 / 28〜（厳重警戒・危険）赤。暑さ側は温度でなく暑さ指数で判定（右上の丸は注意 21〜 から黄だが、数字は警戒から）
  - 湿度: 35% 以下 黄（乾燥）/ 70% 以上 青（多湿）
  - 気圧: 変えない
  - 色: 黄 #FFC107 / 赤 #FF6B5E（カード面で読めるよう明るめ）/ 青 #4FC3F7
- 各カードに直近 1 時間のミニグラフと傾向の矢印（直近 10 分の変化: CO2 ±30ppm, 温度 ±0.3℃, 湿度 ±1.5%, 気圧 ±0.5hPa）
- カードをタップ → グラフ画面。カードは画面いっぱいの 2×2（v1.1 で下段の派生指標の帯を廃止し、カードの高さ 248→292px）。アラームの文はステータスバーに出る
- アラーム中は下部に標準語の帯を表示

### 5.3 グラフ画面（共通部品）

- 上部タブ: 温度 / 湿度 / 気圧 / CO2（センサー画面のカードと同じ順。v1.1 で露点・不快指数・暑さ指数を廃止。タブの最小幅 150px）
- 範囲: **直近 12 時間に固定**（1分値。期間の切り替えボタンはない。v1.1）
- 各センサーの系列を同じグラフに重ねて表示。凡例タップで表示/非表示
  - 例: 温度 = SHT35 / SCD41補正 / BMP581（SCD41生値は初期非表示）
- 平均を線、1分の最小〜最大を薄い帯で表示。欠測は線を途切れさせる
- 長押し + ドラッグでクロスヘア（時刻と各系列の値を表示）
- 閾値ライン（CO2 1000/1500、WBGT 25/28/31 など）を破線で表示
- 戻る: 「◀戻る」ボタン / 右方向のスワイプ（グラフ本体の上ではクロスヘア操作を優先）
- 実装: グラフ本体は PSRAM のキャンバスに、データ・系列の変更時だけ描く（描画 25〜36ms）。クロスヘアと吹き出しは上に重ねた小さな部品
- 配色: dataviz 既定パレット（暗色）の先頭 4 色 #3987E5 / #D95926 / #199E70 / #C98500。カード面 #1A1F27 に対して色覚多様性・コントラストの検証済み。2 系列以上で凡例（タップで表示切替）。文字は文字色、系列色は線と凡例の印のみ
- 時刻未設定のときの横軸は「-4時間」、吹き出しは「7時間2分前」のような相対表記

## 6. データ保存

### 6.1 RAM（PSRAM）

- 9系列 × 1440 点（24h）× {平均, 最小, 最大 (float), 有効数} のリングバッファ
- 約 160KB。直近 1 時間の 10 秒値（スパークライン用）も保持

### 6.2 フラッシュ永続化（SD 不要）

- 専用パーティション 512KB に **1分ごとに 1 レコード追記するリングログ**
- レコード（96B 固定）: magic, 連番, UNIX 時刻, フラグ, 9系列 × {平均, 最小, 最大} を int16/uint16 に固定小数点化（温度・湿度 ×100、気圧 hPa×50）, 有効数, CRC32
- 512KB ≒ 5,400 レコード ≒ 3.7 日分。1セクタの消去は約 3.7 日に 1 回なので、書き込み寿命の心配はない
- 起動時に連番が最大の位置を探し、直近 24 時間分を RAM に復元
- 停電時に失うのは最大 1 分ぶん
- 設定値は NVS（`settings/v2`。v1.1 で項目が変わったため、v1 の設定は初期値に戻る）

### 6.2.1 SD カードへの CSV 書き出し（v1.1）

- microSD（SDMMC 4bit, BSP の `bsp_sdcard_mount`）。カード検出ピンがないので、起動時・1 時間ごと・「カードを確認」「今すぐ書き出す」で確認する。カードがなければ何もしない（自動書き出しのスイッチとボタンは無効表示）
- 書き出し先: `/ENVLOG/YYYYMMDD.CSV`（現地日付で 1 日 1 ファイル。模擬センサーのデータは `/ENVSIM/`）。長いファイル名は無効のまま（8.3 形式）
- 列: `time,co2_ppm,temp_c,rh_pct,pressure_hpa,temp_sht_c,temp_scd_c,temp_bmp_c,temp_scd_raw_c,rh_sht_pct,rh_scd_pct,rh_scd_raw_pct,dew_point_c,discomfort,wbgt_c,crc`。temp_c / rh_pct は採用中の値（SHT35、なければ代わりのセンサー）。欠測は空欄。時刻は `2026-10-17 14:05`（JST）
- 対象: RAM の直近 24 時間のうち、ファイルにまだない分（現在の分は未完成なので除く）。再開位置は**ファイル自身の最後の有効な行**から決める（状態を NVS に持たない）
- 時刻が未設定のときは書き出さない
- **電源断への備え**: ファイルは追記だけ（書き換えない）。書き終えたら `fsync` して閉じる。各行の最後に、その行（最後のカンマの前まで）の CRC-32 を付ける。書き込み中に電源が切れて途中で切れた行・壊れた行は CRC で見分け、読む側と次の書き出しで無視する（次の書き出しは改行を補ってから続ける）。万一 FAT が壊れても、本体フラッシュに元の記録があるので作り直せる
- 書き出しは 1 時間に 1 回、数十 ms〜数秒。それ以外の時間はいつカードを抜いてもよい
- 行の生成と検証は `components/core/csvlog.c`（ホスト単体テスト付き）、カードとファイルの操作は `components/sdlog`

### 6.3 メモリ見積もり

| 用途 | サイズ |
|---|---|
| フレームバッファ 720×1280 RGB565 × 2 | 約 3.7MB |
| 回転用バッファ | 約 1.8MB |
| 1分値リング + 10秒値 1h | 約 0.2MB |
| LVGL ヒープ・フォント展開など | 数 MB |
| **合計** | **PSRAM 32MB の 3 割未満** |

フラッシュ: アプリ + フォント（約 1〜2MB）+ 音声（約 1.3MB）+ ログ 512KB → 16MB に十分収まる。

### 6.4 時刻の扱い

- 時刻は設定画面の「時計」で手動で合わせる（v1.1。NTP は廃止）。システム時刻と RTC（RX8130、UTC、ユーザー RAM の目印つき）に書き込み、起動時は RTC から復元（電圧低下フラグが立っていないときだけ採用）。RTC は月に 1 分程度ずれうる
- 起動時に RTC の時刻が無効な場合: レコードを起動からの経過時間で記録し、時刻を合わせた時点で時刻を逆算して付け直す。画面の時計は「--:--」、診断は「未設定」
- 時刻を合わせ直すと、その起動のアンカーを書き直して履歴を組み直す（`datastore_set_clock`。datastore のタスク内で処理）
- 停電で空いた期間はグラフ上で欠測として扱う
- ESP32-P4 はリセット後もシステム時刻を保持するため、2025〜2100 年の範囲外は無効扱い（2100 年以降の値は起動時に 0 に戻す）。手順2の実機確認で 2152 年の値が残っていたことによる
- 時刻が合うまでは「起動番号＋起動からの経過分」で記録し、時刻が合った時点でアンカー記録を書いて履歴を実時刻で組み直す。時刻が合わないまま終わった起動の記録は、実時刻モードではグラフに置けないため表示しない（相対時刻モードでは起動ごとに 1 分空けて並べる）
- 模擬センサーのデータは `REC_FLAG_SIM` 付きで記録し、実センサーで動くときは読み込まない（手順7で実センサーに切り替えたとき、模擬データが混ざらない）

## 7. 描画最適化（チラつき防止）

- ダブルバッファ + VSYNC 同期でバッファを切り替え（ティアリングなし）
- 回転・塗りつぶし・ブレンドは PPA / DMA2D に任せる。色形式は RGB565
- ラベルは文字列が変わったときだけ更新。等幅数字 + 固定サイズの枠で、再描画範囲を最小にする
- 更新頻度の高い部分に大きな影や半透明の重なりを置かない
- グラフ: グリッドと軸は一度だけ描画。1440 点は横ピクセル数に合わせて列ごとの最小・最大に間引く。再描画は新しい 1 分値が来たとき・タブ/範囲切り替え時・操作中だけ
- アニメーション中だけ描画（約 32〜35fps、§2.1.1）、それ以外は描画しない

## 8. アラーム

### 8.1 条件と文言

| グループ | レベル | 発報 | 解除 | 音声（ずんだもん） | 画面の帯 |
|---|---|---|---|---|---|
| CO2 | 注意 | ≥1000ppm | <900 | co2_caution | 二酸化炭素濃度が高めです。換気してください |
| CO2 | 警告 | ≥1500ppm | <1400 | co2_warning | 二酸化炭素濃度がとても高いです。すぐに換気してください |
| 熱中症 | 警戒 | WBGT ≥25 | <24 | heat_caution | 熱中症に注意してください |
| 熱中症 | 厳重警戒 | WBGT ≥28 | <27 | heat_severe | 熱中症の危険が高まっています |
| 熱中症 | 危険 | WBGT ≥31 | <30 | heat_danger | 熱中症の危険があります。すぐに室温を下げてください |
| 湿度 | 乾燥 | ≤35% | >38 | humidity_low | 空気が乾燥しています |
| 湿度 | 多湿 | ≥70% | <67 | humidity_high | 湿度が高くなっています |
| 温度 | 低温 | ≤16℃ | >17 | temp_low | 室温が低くなっています |
| 気圧 | 急低下 | 3時間で −3hPa 以上 | 変化 > −2hPa | pressure_drop | 気圧が急に下がっています |


### 8.2 タイミング（10秒値で判定）

- あるレベルの条件が **5 分続いたら 1 回** アナウンス
- その後も続いている間は **30 分ごと** にアナウンス
- 同じグループ内でレベルが上がったら、新しいレベルで 5 分の判定をやり直す（上のレベルが優先）。下がったときは再アナウンスしない
- 複数グループが同時に発報したら、キューに入れて 1 秒間隔で順番に再生
- 種類ごとに設定で OFF にできる（画面の帯は OFF でも表示）

### 8.3 おやすみモード（v1.1 で廃止）

- 設定を単純にするため廃止。音声を止めたいときはアラームの種類ごとの ON/OFF を使う。判定ロジック（`core/alarm.c`）のおやすみ関連の入力は残っているが使っていない

### 8.3.1 実装メモ（手順4）

- 判定ロジックは `components/core/alarm.c`（ホスト単体テスト付き）。レベルごとに「そのレベル以上になった時刻」を持つので、警告→注意に下がっても注意の 5 分は途切れない。同時に複数レベルを満たしたら上位だけを流す
- 入力は 10 秒値: CO2、暑さ指数（主の温度・湿度から推定）、湿度、温度。気圧の急低下は 1 分値の履歴から「3 時間前（±5 分の平均）− 直近 5 分の平均」
- 種類ごとの OFF は音声だけを止め、状態判定と画面の帯は続ける
- 画面の帯はステータスバー（ページ名の右）に、色の丸 + 標準語の文。最も優先度の高いものを 1 つ表示
- 明るさの出力は `controller` が設定の値を反映する
- 設定は `components/settings`（NVS の blob）。明るさのスライダーは動かしている間はプレビューのみ、指を離したときに保存

### 8.4 音声データ

- `assets/voice/*.wav`（16kHz / モノラル / 16bit, 合計約 1.3MB）をフラッシュに埋め込む
- 生成: VOICEVOX エンジン（localhost:50021）起動中に `python3 tools/gen_voice.py assets/voice`
- 話者: ずんだもん（ノーマル, ID=3）。クレジット「VOICEVOX:ずんだもん」を設定画面に表示

## 10. デモ（手順6、最小構成）

- デモ画面で **シナリオ** と **速さ** を選んで「デモを開始」。開始中は「最初から再生」（選び直したシナリオで再開）と「デモを終了」
- シナリオ（`components/core/demo.c`。時刻の関数で、ノイズも時刻のハッシュから作るので再現性がある。ホスト単体テストで、各シナリオが狙いのアラームを鳴らし、通常の一日は鳴らないことを確認）:

| シナリオ | 内容 | 鳴るアラーム |
|---|---|---|
| 通常の一日 | 温度 23±1.5℃・湿度 50±6%（16 時ピーク）、CO2 は朝と夜に 860ppm 前後、気圧の日変化 | なし |
| CO2 上昇（会議室） | 40 分で 1900ppm へ、100 分後に換気 | CO2 注意 → 警告 |
| 猛暑 | 1 時間で 34.5℃ / 65%（暑さ指数 32）、3 時間後に下がる | 熱中症 警戒 → 厳重警戒 → 危険 |
| 冬の乾燥 | 30 分で 14.5℃ / 25%、2.5 時間後に戻る | 乾燥・低温 |
| 気圧の急降下（台風） | 4 時間で −8hPa（−2hPa/時）、10 時間後から戻る | 気圧の急低下 |

- 速さ: ×1 / ×60（×60 では「5 分続いたら」が 5 秒、「30 分ごと」が 30 秒。実機で CO2 は開始 21 秒で注意・31 秒で警告、猛暑は 31・41・53 秒で 3 段階、気圧は 100 秒で発報し 30 秒後に再通知）
- 開始時刻はいまの時刻（時刻未設定なら 2026-10-17 09:00）。直前 24 時間ぶんの「通常の一日」を最初から入れるので、グラフもすぐ見られる
- 実装: センサーのタスクがデモの時計を 1 秒ごとに速さぶん進め、10 秒値・1 分値をシナリオから作る。表示値・アラーム（デモの時計で判定）・`datastore_lock()` の履歴がデモに切り替わる。デモの履歴は RAM の別領域で、**フラッシュにも SD にも書かない**。その間も実際の計測は続き、本番の履歴とフラッシュ・SD に記録される
- 開始・終了でアラームの状態をリセットし、画面の帯もすぐ消す（デモのアラームが本番に残らない）
- 表示: ステータスバーに「DEMO ×60 17:06」（デモの時刻）、カードの出所は「SHT35・デモ」。上部の時計は実時刻のまま
- 廃止: 故障の再現（値の飛び・CRC エラー・センサーの抜け）、×10。センサー未接続時の「デモで起動しますか？」は手順7で検討
- 開発用コンソール: `demo シナリオ番号 速さ`（例 `demo 1 60`）、`demo stop`
- アナウンス試聴（9 種類）と音量は従来どおり
